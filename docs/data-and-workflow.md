# Data and workflow

## Input contract

CSV headers are case-sensitive except for the universe. Use UTF-8, quoted fields when required and ISO 8601 timestamps with explicit UTC offsets. The CLI shows times in `Asia/Kolkata`. Five-minute candle times are **start times** and a candle is available when its end time is at or before the requested clock. Keep one historical identity per symbol in an input set. For renamed, newly listed or delisted names, resolve continuity by ISIN and your provider’s dated identifier map before preparing bars.

| Input | Required headers and rules |
| --- | --- |
| Candles | `symbol,ts,open,high,low,close,volume`. INR prices for equities, point levels for indices, volume in shares. Index volume can be zero. Exact duplicate bars across files are deduplicated. Conflicting duplicates reject the input. Auction and out-of-session candles are excluded. Use the `source` column or archive name to preserve provenance. |
| Universe | `symbol`, or an official constituent CSV with `Symbol`, `Series`, `Industry` and `ISIN Code`. Non-`EQ` rows are filtered when a series is supplied. Keep membership snapshots for historical work. The scanner reports requested, received and missing charts. |
| Instruments | `symbol,exchange,series,isin,sector,tick_size,lower_band,upper_band,status,asof,source,instrument_key`. `instrument_key` may be blank. A paper ticket requires an ISIN and documented same-day source. Use `clear` only after checking NSE main-board cash class, intraday eligibility, price ranges, exchange surveillance and current broker restrictions. Status values such as `asm`, `gsm`, `esm`, `t2t`, `halted` or `unknown` fail paper admission. For a dynamic operating range, record current lower/upper limits from the broker or exchange. The simulator uses the range captured in the approved ticket. Refresh on changes and reconcile using dated evidence. |
| Events | `symbol,published_at,event_at,kind,source,title,url`. Use `*` for market-wide notices. `event_at` may be blank and `published_at` is when the item became public. Use `results`, `board-meeting`, `corporate-action`, `regulatory`, `halt`, `order-win`, `m-a`, `rbi-mpc`, or `union-budget` for material-event tags. `disclosures` selects `bulk-deal`, `block-deal`, `pit`, `sast`, `shareholding`, and `pledge`. Add the actual filing link in `url`. |
| Results | `symbol,published_at,period_end,period_months,basis,metric,value,unit,source_url`. Compare three-month rows in the same basis. Use `consolidated` or `standalone`. Supported units are `inr`, `inr-lakh`, `inr-million`, `inr-crore`, `inr-per-share`, and `pct`. The latest filed revision available as of the requested time wins. Enter bank-specific measures under their own labels. |
| Alerts | JSON array. A clock rule needs `id`, `kind: clock`, and `start_at`. A level rule needs `id`, `kind: touch-below` or `touch-above`, `start_at`, `symbol` and `level`. Use a fresh ID for each distinct alert. State is local to the alerts SQLite file. |
| Calendar | Model `id`, `start`, `end`, a `holidays` map and an `exceptions` map. `regimes` must cover every date once. Regular exceptions supply `hours` as `[open, close]`. An `excluded` exception supplies a `note`. Start, end and holiday dates are inclusive calendar dates. |

When collecting bars, request a rolling window before the test period so the strategy can compute prior closes and the relative-volume baseline. `fetch-bars` reads one symbol per call. For intraday history, request date windows of at most 31 calendar days within the broker’s one-month limit, using multiple CSV files for longer spans. The adapter saves only candles already complete when the request starts. Use distinct output files or intentionally overwrite a current-session file. Filter corporate-action discontinuities consistently, and retain source versions and release times for reproducible runs. Respect source retention and sharing terms. ## Research and paper session

1. Use `premarket` for completed daily structure, turnover, ATR, RSI and contraction. Import the current-day calendar and events. Cross-check earnings, index rebalance, major RBI or Budget events and surveillance updates.
2. Use `scan` to inspect coverage and candidates. `entry` explains newly confirmed, previously confirmed, waiting, expired or blocked setups. Use `--benchmark NIFTY50` or an aligned industry index in the same format. An explicitly supplied benchmark with a missing slot blocks confirmation. The scan’s breadth compares observed equities with their session opens. It describes the supplied universe and is only available while scan metrics can be evaluated.
3. Use `plan` for the structural stop and target. Replay the same setup and target with realistic units, fees and slippage. Check sample size, unfilled and unresolved rates, and the mix of regimes before interpreting conditional percentages. Use out-of-sample dates and historical universe membership to evaluate thresholds.
4. Use `ticket` to calculate full-notional sizing in INR from paper cash and modeled worst allowed entry, stop slippage and statutory charges. The paper gate rechecks current session, timestamp, restriction flags, tick/band evidence, drift, net reward/risk, committed risk, exposure and daily limits. Run `paper-confirm` only after reviewing the digest for the exact ticket. A successful confirmation queues a paper order. It does not report an entry fill.
5. Supply fresh bars to `paper-advance`. A bar with both stop and target takes the stop first. Gaps use an adverse stop price. A price touch on a missing, zero-volume or locked bar can leave an exit unresolved. `paper-status` reads the current local ledger for the selected date. `paper-cancel` can revoke a pending simulation. `paper-reconcile` records operator-supplied evidence for an open simulated position when a same-session fill cannot be reconstructed from available bars. The reconciliation clock is the observed exit time and needs to be within that session.
6. Use `alerts` for one-shot observations when checking refreshed data. Its bar alerts are completed-candle observations, so the report time is the candle close and can trail the actual touch.

The defaults use a 15-minute opening range and at least five prior modeled sessions for liquidity and relative volume, with a 20-session median window. The first confirmation is at 09:35. Sample filters include ₹10 crore median modeled daily turnover, 1.15× cumulative relative volume, 1.35× bar relative volume, a 350 bp absolute opening-gap limit, and limits on opening-range width and trigger extension. `SignalRules` documents all overridable fields. `RiskConfig` defaults to no new fills from 14:45 and a 15:05 flat deadline, clipped earlier for shortened sessions. ## Model boundaries

A five-minute candle provides a volume and price range, with no sequence or executable depth. The simulator uses an adverse stop-first rule for an ambiguous bar. A halt or a gap can exceed modeled loss or leave an unclosed position. The fee model estimates one buy and one sell, with a dated configurable Zerodha NSE intraday schedule and default 5 bp slippage each way. It excludes broker-specific penalties, intraday auto-square-off fees and income tax. The measured opening gap uses the previous modeled continuous close, which can differ from an official auction or settlement close.

Exchange-rule coverage includes the packaged 2026 calendar and a same-day instrument snapshot at ticket review. Dynamic surveillance, halts and special sessions require updated source data. The offline demo proves the software flow with synthetic bars. Historical research requires licensed or permitted Indian data with point-in-time event and membership coverage.
